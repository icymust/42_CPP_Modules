# CPP Module 05 — сводка ex00–ex03

Модуль закрепляет классы, наследование и полиморфизм и знакомит с исключениями.
Код написан для C++98; флаги сборки: `-Wall -Wextra -Werror -std=c++98`.

## Ex00 — Bureaucrat: чиновник и исключения

У чиновника неизменяемое имя и ранг от **1 до 150**. Число 1 — высшая должность.
Повышение уменьшает число, понижение увеличивает.

- Ранг меньше 1: `GradeTooHighException`.
- Ранг больше 150: `GradeTooLowException`.
- Проверка выполняется в конструкторе и перед изменением ранга.
- Если изменение невозможно, выбрасывается исключение, прежний ранг сохраняется.
- Геттеры читают поля, `operator<<` выводит `Martin, bureaucrat grade 42.`.

### Новое: обработка ошибок

| Запись | Значение |
|---|---|
| `try { ... }` | Код, из которого может прийти исключение |
| `throw Error();` | Выбросить объект ошибки и прервать обычное выполнение |
| `catch (const std::exception& e)` | Перехватить стандартное исключение или его публичного наследника по ссылке |
| `std::exception` | Базовый класс стандартных исключений |
| `e.what()` | Получить описание ошибки как `const char*` |
| `what() const throw()` | Метод не меняет объект и обещает не выбрасывать исключений, синтаксис C++98 |

```cpp
try {
    Bureaucrat bob("Bob", 0);
} catch (const std::exception& e) {
    std::cout << e.what() << std::endl;
}
```

После `throw` остаток соответствующего `try` пропускается. Обработчик ищется
по цепочке вызовов. Если подходящего обработчика нет, программа завершается.
При распространении исключения уничтожаются уже созданные локальные объекты;
сырые указатели сами не удаляют объекты, на которые указывают.

Свои классы ошибок публично наследуются от `std::exception` и переопределяют
`what()`. Вложенность даёт имя `Bureaucrat::GradeTooHighException`.
Классам исключений по subject не обязательна Orthodox Canonical Form.

## Ex01 — Form: подпись документа

У документа четыре приватных поля:

- неизменяемое имя;
- статус подписи, изначально `false`;
- неизменяемый ранг для подписи;
- неизменяемый ранг для исполнения.

Оба ранга проверяются при создании: допустимы значения 1–150.

`Form::beSigned(bureaucrat)` проверяет полномочия и меняет статус на `true`.
Для подписи требуется `bureaucrat.getGrade() <= gradeToSign`.
При недостаточном ранге выбрасывается `Form::GradeTooLowException`.

`Bureaucrat::signForm(form)` вызывает `beSigned(*this)` внутри `try`, а затем
сообщает об успехе либо ловит исключение и печатает причину отказа.

### Что закрепляем

- **Разделение ответственности:** документ решает, можно ли его подписать;
  чиновник пытается подписать и сообщает результат.
- **Список инициализации:** поля `const` задаются до тела конструктора.
- **Копирование и присваивание:** конструктор копирования задаёт все поля нового
  объекта; оператор присваивания существующего `Form` копирует только статус,
  потому что остальные поля `const`. У `Bureaucrat` копируется только ранг.
- **Предварительное объявление:** `class Form;` достаточно для объявления
  параметра-ссылки или указателя. Чтобы вызвать методы, в `.cpp` подключается
  полный заголовок. Это устраняет цикл взаимных `#include`.

## Ex02 — AForm: абстрактный класс и исполнение

`Form` переименован в `AForm`. Общие поля остались приватными в базе.
Добавлены три наследника:

| Документ | Подпись | Исполнение | Действие |
|---|---:|---:|---|
| `ShrubberyCreationForm` | 145 | 137 | Файл `<target>_shrubbery` с ASCII-деревьями |
| `RobotomyRequestForm` | 72 | 45 | Звуки сверления; вероятность успеха роботизации 50% |
| `PresidentialPardonForm` | 25 | 5 | Сообщение о помиловании цели Zaphod Beeblebrox |

`target` — цель действия, например `garden` или `Bender`.
Ранги и имя вида документа задаёт конкретный класс.

В нашей реализации `AForm::execute(executor)`:

1. Проверяет подпись, иначе выбрасывает `NotSignedException`.
2. Проверяет `executor.getGrade() <= gradeToExecute`, иначе выбрасывает
   `GradeTooLowException`.
3. Вызывает `executeAction()` соответствующего наследника.

`Bureaucrat::executeForm(form)` вызывает исполнение и печатает успех либо отказ.
Неудачная роботизация — предусмотренный результат действия, а не ошибка прав
доступа: сообщение `executed` после неё допустимо.

### Что нового

- **Абстрактный класс:** имеет хотя бы один чисто виртуальный метод, поэтому
  напрямую создать его объект нельзя.
- **Чисто виртуальный метод:** `virtual void executeAction() const = 0;`.
  Конкретные наследники обязаны дать реализацию, чтобы их можно было создавать.
- **Полиморфизм:** через `AForm&` или `AForm*` вызывается действие реального
  наследника. Общие проверки написаны один раз в базе.
- **`protected`:** метод действия доступен наследникам; данные базы остаются
  `private`. Действие не вызывается снаружи в обход проверок.
- **Виртуальный деструктор:** `virtual ~AForm();` обеспечивает правильное
  уничтожение наследника при `delete` через `AForm*`.
- **Файлы:** `std::ofstream` создаёт файл; ошибки открытия и записи проверяются.
- **Псевдослучайность:** `std::rand() % 2` выбирает один из двух исходов.
  `std::srand()` вызывается один раз в `main`. Вероятность 50% не означает,
  что ровно половина небольшого числа запусков обязательно будет успешной.

## Ex03 — Intern: создание документа по строке

У `Intern` нет имени, ранга и собственных данных. Главный метод:

```cpp
AForm* makeForm(const std::string& name, const std::string& target) const;
```

| Строка `name` | Создаваемый класс |
|---|---|
| `shrubbery creation` | `ShrubberyCreationForm` |
| `robotomy request` | `RobotomyRequestForm` |
| `presidential pardon` | `PresidentialPardonForm` |

Метод создаёт объект через `new`, выводит `Intern creates <form>` и возвращает
указатель на базовый класс. Неизвестное имя в нашей реализации приводит к
понятному сообщению и возврату `NULL`; subject требует сообщение, но не задаёт
конкретный способ возврата ошибки.

### Что нового

- **Фабрика:** код выбирает конкретный класс по входным данным и возвращает
  общий тип `AForm*`. Вызывающему коду не нужно выбирать конструктор самому.
- **Указатель на функцию:** таблица связывает строки с функциями создания.
  Вместо длинной цепочки `if/else` используется один цикл и одна проверка.
- **`typedef`:** даёт короткое имя типу указателя на функцию:
  `typedef AForm* (*Factory)(const std::string&);`.
- **Владение памятью:** вызывающий код обязан удалить возвращённый объект.
  Перед использованием результата нужно проверить, что он не `NULL`.
- **`catch (...)`:** перехватывает исключение любого типа; в демонстрации
  освобождает объект, а `throw;` передаёт исходное исключение дальше.

```cpp
Intern intern;
AForm* form = intern.makeForm("robotomy request", "Bender");
if (form) {
    // Подписание и исполнение.
    delete form;
}
```

Если между получением указателя и `delete` может возникнуть исключение,
необходимо обеспечить освобождение памяти и на этом пути, как в `src/main.cpp`.

## Сборка и демонстрация

В папке нужного упражнения:

```sh
make
./bureaucrut
```

Имя `bureaucrut` сохранено из существующих Makefile.
Ex02 создаёт `home_shrubbery`, ex03 — `garden_shrubbery` в текущей рабочей папке.

В main оставлены примеры для показа на защите. Ex02 демонстрирует подпись,
недостаточный ранг, исполнение и наследование. Ex03 показывает три известных
имени, неизвестное имя и освобождение созданных объектов.

## Что уметь объяснить на защите

1. Почему ранг 1 выше 150 и почему используется сравнение `<=`.
2. Чем `throw` отличается от `return` и куда переходит управление.
3. Зачем ловить исключение по ссылке и что возвращает `what()`.
4. Чем инициализация `const` отличается от присваивания.
5. Почему `AForm` нельзя создать напрямую, но можно использовать `AForm*`.
6. Как выбирается `executeAction()` и зачем виртуальный деструктор.
7. Как `Intern` выбирает фабричную функцию и кто вызывает `delete`.
